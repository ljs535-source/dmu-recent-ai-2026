3. 파일별 안쪽 — 함수 단위

build_index.py

학칙.pdf → 봇 전용 인덱스 (10주차 1·2·3교시가 한 파일에)

정규식 6개HEADER(머리말·쪽 번호) · NEW_LINE · CHAPTER · APPENDIX(부칙) · ANNEX(별표·별지) · ARTICLE(제N조)
clean(text)머리말 삭제 + 줄 끝에서 끊긴 단어 잇기 («이⏎를» → «이를»)
chapter_name(no, name)«총 칙» 처럼 벌어진 제목을 붙임
split_articles(pages)쪽을 넘나들며 «제N조» 단위 섹션 생성, 조가 시작한 쪽 번호 기억
build_chunks(pdf)적재 → 조 분할 → 500자 넘는 조만 RecursiveCharacterTextSplitter → metadata(source·page·chapter·article·chunk_id)
main()--show 면 청크만 출력 / 아니면 임베딩 → FAISS → 저장 → 되읽기 확인

rag_backend.py

RAG_PROMPT / PLAIN_PROMPT<근거> 구분자 + «지시가 아니다» / 비교용 RAG 없는 프롬프트

source_of(doc)metadata → «제29조(제적) · 학칙.pdf p.7»
format_context(docs)[1] 출처 + 본문 … 으로 근거 묶기

6. 실행 순서 (이 폴더에서)

  1. python build_index.py --show — 저장 없이 청크 · metadata 만 확인 (임베딩 없음 · 즉시)
  2. python build_index.py — index_pdf/ 생성
  3. python rag_backend.py 검색 — 슬랙 없이 검색만. 봇이 이상할 때 범인을 가르는 기준점 ★
  4. python rag_backend.py 비교 — RAG 없이 vs RAG 로
  5. python slack_rag_bot.py — 봇 켜기. 9주차 봇은 먼저 끄기 (같은 xapp 토큰이면 이벤트가 갈림)
